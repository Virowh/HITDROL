# Перенос HITDROL на другой компьютер

Состояние на 14 ноября 2026: HITDROL Beta 0.1, внутренняя версия сборки **0.4.9**. Это исходники приложения для Windows 11 x64 на Rust / winit / wgpu / egui. Полная инструкция находится в README.md, история проверок — в QA.md.

Публичный репозиторий исходников: [Virowh/HITDROL](https://github.com/Virowh/HITDROL), ветка `main`. Подготовлены `docs/PUBLICATION-AUDIT.md` и черновик `docs/DTF-POST.md`. Готовые пакеты приложения публикуются в [GitHub Releases](https://github.com/Virowh/HITDROL/releases). История Git начата заново из проверенного снимка архива. Сценарий `.github/workflows/windows-release.yml` собирает и проверяет Windows-пакеты с зафиксированными зависимостями, статической CRT и нейтральными путями компиляции. Числовая версия повышена для обновления с 0.4.8; игровая функциональность сохранена.

## Продолжение работы в Codex

Распакуйте архив целиком, откройте полученную папку как проект в Codex и попросите прочитать этот файл, README.md и последние записи QA.md. Сам архив не содержит историю переписки Codex.

Для сборки нужны Rust stable с MSVC toolchain (версия Rust не ниже указанной в Cargo.toml), Visual Studio Build Tools с C++ и Windows SDK. Скрипты сборки используют PowerShell 7 (`pwsh`). Первое скачивание зависимостей требует интернета. Сборочный кэш в архив не включён и будет создан заново.

```powershell
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
cargo build --release --locked --bin hitdrol-launcher
cargo run --locked -- --demo 12 --windowed --data-dir artifacts/demo
pwsh -File scripts/package.ps1
pwsh -File scripts/build-installer.ps1 -SkipPackage
```

Сохраняйте оба Cargo.lock: корневой и installer-actions/Cargo.lock. Используйте зафиксированные зависимости; среди них есть отозванная версия clipboard-win, с которой работали существующие locked-сборки. Обновление зависимостей — отдельная задача.

## Последние изменения

- Автозапуск — обычная запись Run текущего пользователя, по умолчанию выключена и управляется через автозагрузку Windows. Раннее задание больше не создаётся; early_start.rs содержит только удаление прежнего задания. Старый аргумент --early-autostart сразу завершает новый EXE.
- Автозапуск ждёт разблокированного стабильного сеанса до открытия базы, GPU и звука. Если Windows не дала фокус, показывается библиотека без заставки. Имитация клавиш для получения фокуса удалена.
- У запущенной игры кнопка «Играть» заменяется красной «Закрыть игру» на том же месте. Закрытие через WM_CLOSE только для подтверждённого процесса игры; принудительного завершения процессов нет.
- Автоматическое сканирование не показывает сообщение об успешном завершении. При ручном обновлении сообщение остаётся.
- В 0.4.8 прошли 87 тестов и Clippy, проверены таблицы MSI, флажки и выбор папки без установки на ПК разработчика. Реальную перезагрузку/автозапуск Windows, геймпад, сенсор и работу конкретных игр проверяет пользователь на портативке. Сборочные журналы и скриншоты удалены при очистке; проверки можно повторить.

## Состав проекта и пользовательские данные

`src`, `assets`, `tests`, `scripts`, `installer-actions`, `.cargo`, Cargo.toml, оба Cargo.lock и build.rs нужны для разработки. `target`, `installer-actions/target`, `artifacts` и `dist` создаются заново и не входят в архив исходников. Папки artifacts и dist при необходимости можно создать командой `New-Item -ItemType Directory -Force artifacts,dist`.

Библиотека, настройки и кэш установленного HITDROL находятся отдельно: `%LOCALAPPDATA%\HITDROLLauncher`. Они не входят в этот архив. Токены и ключи хранятся через Windows Credential Manager и также не переносятся вместе с исходниками.

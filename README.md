# HITDROL Beta 0.1

Репозиторий: [github.com/Virowh/HITDROL](https://github.com/Virowh/HITDROL). Внутренняя версия сборки — **0.4.9**. Установщик MSI и портативный ZIP приложения публикуются в разделе [Releases](https://github.com/Virowh/HITDROL/releases). Автоматические архивы **Source code** содержат исходники и требуют самостоятельной сборки по разделу «Разработка и проверка».

Локальная библиотека игр для портативных устройств с Windows 11 x64. Rust, winit, wgpu и egui. Интерфейс на русском, управление геймпадом XInput, сенсором, мышью и клавиатурой.

## Запуск

**Установщик:** откройте `HITDROL-Beta-0.1-windows-x64.msi`. Папку можно вписать в поле **Папка установки** или выбрать через **Обзор…**: диск → папки → **Выбрать**. По умолчанию — `%LOCALAPPDATA%\Programs\HITDROL`; можно выбрать другую папку с правом записи, включая другой диск. Установка выполняется для текущего пользователя, без прав администратора. В мастере можно выбрать ярлык на рабочем столе и автозапуск. Автозапуск по умолчанию выключен. Приложение появляется в меню «Пуск» и в списке установленных приложений Windows. Перед обновлением закройте HITDROL. MSI Beta 0.1 обновляет ранее установленные версии и сохраняет профиль; при установке снова выберите нужный автозапуск.

Для удаления используйте **Параметры Windows → Приложения → Установленные приложения → HITDROL → Удалить**. Файлы приложения, ярлыки и собственная запись автозапуска удаляются; библиотека, оформление и настройки в профиле сохраняются. Повторный запуск MSI позволяет восстановить или удалить установку.

**Портативная версия ZIP:**

1. Распакуйте **весь ZIP** в удобную папку.
2. Запустите **HITDROL.exe**. По умолчанию откроется полный экран, установленная библиотека найдётся в фоне.
3. Откройте карточку и нажмите **Играть**. Для добавления сторонней игры: **Добавить → выбрать ярлыки → Добавить выбранные**, либо **Другое → диск → папка → файл**.

Для оконного режима нажмите **F11** или выберите его в настройках. Закрыть приложение можно кнопкой **×** вверху или сочетанием **Alt+F4**. Сам HITDROL не требует установки, прав администратора или автозапуска.

## Автозапуск Windows

Выберите его в установщике либо нажмите **Настройки → Экран и оформление → Добавить в автозагрузку**. После добавления HITDROL появится в **Диспетчер задач → Автозагрузка приложений**; там можно включать или отключать запуск при входе в Windows. Кнопка **Автозагрузка Windows** открывает соответствующий раздел параметров Windows.

Сборка **0.4.8** использует только обычную запись текущего пользователя `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. По умолчанию автозапуск выключен. Статус в HITDROL означает наличие этой записи; разрешение запуска контролирует диспетчер задач. Лаунчер не меняет его решение при повторном добавлении записи. Для ZIP автозапуск привязан к текущему расположению EXE: после переноса папки добавьте его заново.

Прежний ранний запуск через Планировщик удалён. Установщик при обновлении удаляет только прежнее задание HITDROL текущего пользователя. Параметр `--early-autostart` оставлен для совместимости и сразу завершает приложение, без окна, GPU или звука. Если служба Планировщика недоступна, неудачная очистка записывается в журнал MSI и не блокирует установку исправления.

Автозапуск ждёт разблокированного сеанса и доступного рабочего стола, затем проверяет их стабильность две секунды. До этого не открывает базу, не создаёт окно и не инициализирует графику или звук. Через пять минут без готового сеанса процесс завершает ожидание. Если Windows не разрешила получить фокус, сразу показывается библиотека без заставки и звука. При полученном фокусе заставка отсчитывается после показа первого кадра; блокировка приостанавливает отрисовку и звук. Повторный экземпляр одного профиля не открывается. Время выполнения обычной автозагрузки выбирает Windows; запуск раньше Explorer не гарантируется. Системные задержки автозагрузки, оболочка, драйверы, ориентация экрана и службы Windows не меняются.

## Заставка при запуске

При открытии HITDROL проигрывается заставка на **2,5 секунды**: ледяная надпись, удар клинка, небольшой разрез в центре, трещины и осколки, затем плавный переход к библиотеке. Обнаружение игр и загрузка библиотеки продолжаются в фоне. После завершения текстуры заставки освобождаются; отдельного видеоплеера нет.

Отсчёт заставки и звук начинаются после первого успешно показанного GPU-кадра. Подготовка GPU и загрузка ресурсов не отнимают её время. Пока заставка полностью закрывает окно, библиотека под ней не отрисовывается; первый кадр содержит приглушённый ледяной фон, в том числе при ожидании фокуса Windows.

Пропустить: касание/щелчок, **Enter**, **пробел**, **Esc**, **A** или **B** на контроллере. Это нажатие поглощается заставкой. Отключить её можно в **Настройки → Экран и оформление → Заставка при запуске**. При выключенных анимациях заставка также пропускается. В свёрнутом состоянии кадров нет; при потере фокуса время анимации приостанавливается.

Заставка сопровождается коротким звуком: нарастающий ледяной шелест, удар клинка на 1,10 с и затухание осколков. Отключить отдельно: **Настройки → Экран и оформление → Звук заставки**. Звук учитывает системную громкость; при потере фокуса или сворачивании приостанавливается вместе с анимацией, а при пропуске и закрытии останавливается. При отключённой заставке звука нет.

## Вся библиотека и установка игр

В **Настройки → Библиотека** выберите **Только установленные** или **Вся библиотека**. Во втором режиме отображаются принадлежащие аккаунту игры Windows, в том числе ещё не установленные. Откройте такую карточку и нажмите **Установить**. Steam/Epic откроют установку в своём клиенте; GOG Galaxy откроет страницу игры с установкой. Подтверждение, выбор диска, загрузку и обновления выполняет клиент магазина. Для GOG нужен установленный Galaxy. После возвращения в HITDROL список установок обновляется; доступна и кнопка обновления вручную.

**Steam** подключается автоматически: читаются лицензии текущего локального аккаунта, `packageinfo.vdf` и `appinfo.vdf`. Войдите в Steam и откройте его библиотеку хотя бы один раз. Это лицензии аккаунта, а не список файлов обложек. При неполном или отсутствующем кэше HITDROL покажет предупреждение: дождитесь обновления библиотеки Steam и повторите сканирование. Уже сохранённые игры остаются доступны без сети.

Для **Epic Games и GOG** в том же разделе нажмите **Подключить аккаунт**. Откроется официальный сайт магазина. После входа вернитесь в HITDROL: для Epic вставьте `authorizationCode` или весь JSON с ним; для GOG — адрес страницы после входа с параметром `code`. Кнопка **Вставить** работает с сенсора и геймпада; также можно использовать Ctrl+V в поле. Нажмите **Готово**. Пароль вводится только на сайте магазина. Одноразовый код не сохраняется в библиотеке; токен обновления хранится в Windows Credential Manager. В установленном клиенте должен быть выбран тот же аккаунт.

**Отключить** удаляет сохранённый токен и скрывает неустановленные игры этого аккаунта. Установленные игры и пользовательское оформление сохраняются. Ошибка сети не очищает ранее загруженную библиотеку. Данные аккаунтов синхронизируются в фоне при включённом режиме всей библиотеки и по кнопке обновления. Вход Epic/GOG требует ручной проверки с вашим аккаунтом; выполненные проверки перечислены в QA.md.

## Настоящие недавние игры

Главная показывает до 18 игр с подтверждённым временем запуска, от новых к старым. Импортируется `LastPlayed` текущего аккаунта Steam. Новые запуски определяются по процессу игры: вручную добавленные EXE/ярлыки — по точной цели, магазинные игры — по EXE или папке установки. Это работает и для игр, открытых вне HITDROL, пока сам лаунчер запущен. Сворачивание не мешает сохранению истории и не включает отрисовку интерфейса.

Само нажатие «Играть», открытие клиента или установщика не добавляет игру в недавние. Ранее сохранённые неподтверждённые отметки старых версий не используются. Если запусков ещё нет, главная сообщает об этом и предлагает перейти в библиотеку. История Epic/GOG до запуска новой версии не импортируется: будут учтены подтверждённые процессы после её открытия.

## Свои обои и Wallpaper Engine

Откройте **Настройки → Обои лаунчера**:

- **Свои обои → Выбрать изображение**: выберите PNG, JPEG, WebP или ICO во встроенном проводнике. HITDROL сохранит копию в профиле; исходный файл больше не нужен. Обои заполняют окно с сохранением пропорций, края могут обрезаться. Затемнение — 40%, 65% или 80%.
- **Wallpaper Engine → Выбрать живые обои**: список содержит установленные проекты из Workshop, стандартные и собственные проекты. Через диски можно выбрать `project.json`, MP4, WebM или HTML. Поддерживаются Scene, Video и Web; проекты типа Application не запускаются.
- **Стандартный фон** отключает пользовательские обои, сохраняя последний выбор.

Wallpaper Engine приобретается и устанавливается отдельно. **Сначала запустите его через Steam хотя бы один раз**, затем оставьте запущенным. HITDROL обнаруживает установку автоматически; при необходимости нажмите **Папка Wallpaper Engine** и выберите `wallpaper64.exe` или `wallpaper32.exe`. Обе версии поддерживаются. Если движок был закрыт, запустите его и нажмите **Повторить подключение**.

HITDROL открывает отдельное служебное окно обоев за пределами экрана и переносит **только его** кадры в свой фон через Windows Graphics Capture. Рабочий стол не захватывается. Интеграция использует [официальные команды Wallpaper Engine](https://help.wallpaperengine.io/en/functionality/cli.html). Настройки и обои рабочего стола не меняются; глобальные команды pause/stop/play не отправляются.

При запуске игры, потере фокуса или сворачивании HITDROL сохраняет последний кадр, закрывает своё окно обоев и освобождает ресурсы захвата и воспроизведения. После возвращения обои **загружаются заново**, а не продолжаются с прежней секунды. Сам Wallpaper Engine и обои рабочего стола могут продолжать работать по его собственным настройкам. При выходе из HITDROL служебное окно тоже закрывается.

Частота фона в HITDROL — 15/30/60 FPS, по умолчанию 30, разрешение источника ограничено 1280×800 с сохранением пропорций. Это ограничивает получение кадров; качество и частота внутреннего рендера Wallpaper Engine определяются его настройками. Общий ограничитель HITDROL по-прежнему действует. Живые обои требуют больше энергии, чем статичное изображение. При недоступном движке остаётся последнее изображение или стандартный фон, а в настройках показывается причина. После удаления проекта из Workshop выберите другой.

## Управление

| Действие | XInput | Клавиатура |
|---|---|---|
| Перемещение | Крестовина / левый стик | Стрелки |
| Выбрать | A | Enter / пробел |
| Назад / отменить | B | Esc |
| Переключить раздел | LB / RB | PageUp / PageDown |
| Изменить выбранную игру | Menu | Клавиша контекстного меню |
| Полный экран | Настройки | F11 |

Нажатие карточки открывает её страницу. Запуск — отдельной кнопкой. Для поиска и редактирования есть экранная клавиатура RU/EN, доступная геймпаду и сенсору; **поиск открывается на EN**, редактирование названия — на RU. Физическая клавиатура также работает в текстовом поле. После переключения в игру ввод геймпада приостанавливается; после возвращения фокуса сначала отпустите кнопки и стик.

Кнопка «Играть» меняет голубой фон на зелёный при наведении мыши и выделении с геймпада или клавиатуры. При нажатии зелёный фон становится темнее; после ухода указателя обычный цвет возвращается.

После возврата в HITDROL запущенные игры видны в верхней части главной и библиотеки. Откройте активную игру: кнопка **Играть** на том же месте заменяется красной **Закрыть игру**, после выхода снова становится кнопкой **Играть**; кнопка доступна мыши, сенсору и навигации геймпадом. Список обновляется примерно раз в три секунды и при возвращении фокуса. Закрытие отправляет обычное сообщение Windows `WM_CLOSE` только окнам подтверждённых процессов игры. Проверяются путь, PID, точное время создания процесса и сессия Windows. Steam, Epic, Galaxy и вспомогательные процессы не завершаются. Отправленный запрос ещё не означает закрытие: игра может показать подтверждение или проигнорировать его. В таком случае используйте её меню или диспетчер задач. Принудительного завершения и кнопки поверх полноэкранной игры в этой сборке нет.


Автоматическое сканирование при открытии HITDROL и возвращении из игры выполняется без сообщения об успешном завершении. При обновлении по кнопке показывается результат; ошибки библиотеки остаются видны.

## Источники

- **Steam:** локальные библиотеки из `libraryfolders.vdf`, установленные приложения из `appmanifest_*.acf`, локальные обложки Steam. Запуск через Steam URI.
- **Epic Games:** установленные приложения из локальных `.item`-манифестов; запуск через протокол клиента Epic.
- **GOG:** записи установки GOG в реестре и `goggame-*.info`. Запуск через установленный Galaxy, иначе через локальное основное действие игры.
- **Вручную:** `.exe`, `.lnk`, игровые `.url`. Пользовательский и общий рабочий стол определяются через Windows Known Folders, в том числе перенесённый рабочий стол.

Для Steam и Epic нужен установленный клиент с зарегистрированным протоколом запуска. Доступность игр и лицензий проверяет магазин. Подключение аккаунтов нужно только для импорта неустановленных игр Epic/GOG. Повторное обновление сохраняет избранное, своё название, параметры запуска, историю и оформление. Точное совпадение цели запуска или идентификатора магазина объединяется; совпадение только названия — нет. Отключённый диск не удаляет запись.

`.lnk` запускается самим Windows Shell с исходными аргументами и особенностями ярлыка. Для изменения его аргументов укажите в редакторе прямой путь к `.exe`. Ярлык должен оставаться на диске. Страница игры позволяет изменить название, путь, аргументы и рабочую папку.

## Обложки

На странице игры выберите **Обложка из файла** или **Фон из файла**. Встроенный проводник принимает PNG, JPEG, WebP и ICO. Изображение копируется в кэш, исходный файл после этого не нужен. Максимальный размер входного файла — 24 МиБ, сторона — 8192 пикселя.

Ручное изображение имеет приоритет над локальным и загруженным. Для Steam поддерживаются прежние имена изображений и новый `library_capsule`, в том числе в папках с хешами. Если локальной обложки нет, официальные изображения Steam, Epic и GOG загружаются автоматически **без API-ключа** и сохраняются в дисковом кэше. Steam и GOG сопоставляются по ID игры; Epic использует точные CatalogNamespace и CatalogItemId. Для локального импорта Epic нужен каталог `Data/Catalog/catcache.bin`; если он отсутствует, запустите клиент Epic и обновите библиотеку HITDROL. При подключённом аккаунте Epic метаданные неустановленных игр получаются также из API магазина.

В **Настройки → Обложки и фоны** можно выключить загрузку изображений магазинов. Кэшированные изображения работают без сети. Кнопка **Обновить обложки** повторяет поиск и загрузку недостающих изображений. Повреждённая или недоступная пользовательская картинка не блокирует доступную магазинную обложку; пользовательский выбор сохраняется. Ошибка одной игры не останавливает остальные загрузки. Если магазин не предоставляет изображение, остаётся карточка с названием или иконкой и ручной выбор.

Для дополнительного онлайн-поиска можно указать личный [API-ключ SteamGridDB](https://www.steamgriddb.com/profile/preferences/api) в настройках. Ключ хранится в Windows Credential Manager, вне SQLite. При включённой интеграции SteamGridDB отправляются названия игр или Steam ID. Он используется для недостающих обложек и фонов после официальных источников.

Автоподбор использует Steam ID или единственное точное нормализованное совпадение названия. Для остальных случаев нажмите **Найти обложку / Найти фон** и выберите нужную игру, затем изображение. При отсутствии сети и ошибке ключа библиотека и ручные картинки продолжают работать.

## Частота кадров и хранение

В настройках: 30 / 40 / 60 / 90 / 120 / 144 FPS, частота экрана или своё значение 30–240. Это верхний предел кадров интерфейса; FPS игры и режим дисплея не меняются. VSync может дополнительно снижать фактическую частоту. В простое кадры рисуются по необходимости, в свёрнутом состоянии — не рисуются.

Данные: `%LOCALAPPDATA%\HITDROLLauncher\` — `library.db`, кэш `artwork`, `icons`, `wallpapers`, диагностический `last-run.json`. При первом запуске библиотека, избранное, оформление и настройки предыдущей версии автоматически копируются в новый профиль. Исходный профиль сохраняется; уже существующая библиотека HITDROL не перезаписывается. API-ключ переносится в новую запись Windows Credential Manager. Для резервной копии закройте HITDROL и скопируйте папку профиля. API-ключ и токены аккаунтов в копию не входят. Автозапуск добавляется только по вашему выбору в установщике или настройках.

## Разработка и проверка

Нужны Windows 11 x64, Rust stable с MSVC toolchain и Visual Studio Build Tools с компонентами C++ / Windows SDK. Зафиксированные зависимости находятся в `Cargo.lock`.

```powershell
cargo run -- --windowed
cargo run -- --demo 1000 --windowed --size 1280x800 --data-dir artifacts/demo
cargo test --all-targets --locked
cargo clippy --all-targets --locked -- -D warnings
pwsh -File scripts/verify-release.ps1
pwsh -File scripts/verify-intro.ps1
pwsh -File scripts/verify-session-startup.ps1
pwsh -File scripts/package.ps1
pwsh -File scripts/build-installer.ps1
pwsh -File scripts/verify-installer.ps1
pwsh -File scripts/verify-installer-options.ps1
pwsh -File scripts/verify-installer-preview.ps1
```

Сначала соберите release через `cargo build --release --locked --bin hitdrol-launcher`, затем запускайте сценарии проверки. `package.ps1` повторяет проверки и создаёт ZIP. Вспомогательный `hitdrol-launch-probe` нужен только интеграционным тестам и не входит в поставку.

`build-installer.ps1` собирает ZIP, небольшую Rust DLL удаления собственной записи автозапуска и MSI средствами Windows (`WindowsInstaller` COM и `makecab.exe`). Сторонний компилятор установщиков не требуется. Установщик и архив имеют файлы SHA256 рядом с ними в `dist`. `verify-installer.ps1` устанавливает и удаляет приложение в отдельной тестовой папке; при наличии пользовательской установки или записи автозапуска проверка отказывается их заменять.

`verify-installer-options.ps1` проверяет в нативной сессии MSI все четыре сочетания флажков, выбранные **после** расчёта установки, и изменение пути с кириллицей/пробелами. Это отдельная проверка логики мастера, без автоматизации его окон. Обновление с предыдущей сборки проверяется параметром `verify-installer.ps1 -PreviousPackage PATH_TO_PREVIOUS_MSI`.

Для очистки сборочных файлов: `pwsh -File scripts/clean-workspace.ps1` показывает список; добавление `-Apply` удаляет `target`, `artifacts`, вспомогательный target и прежние сборки из `dist`, сохраняя исходники и текущие MSI/ZIP с проверенными контрольными суммами. Скриншоты и старые результаты, на которые ссылаются предыдущие разделы QA.md, после очистки нужно получить повторным запуском проверок.

Обслуживание без открытия окна: `HITDROL.exe --enable-autostart`, `--disable-autostart`, `--clear-store-cache`. Последняя команда отключает сохранённое подключение Epic в HITDROL и очищает кэш владения Steam/Epic; установленные игры, история и пользовательские изменения сохраняются. После неё выбирается режим «Только установленные». Клиенты магазинов и их сессии не изменяются. Steam автоматически читается снова при следующем выборе всей библиотеки. Для другого профиля можно передать `--data-dir PATH`. При запуске этих команд из PowerShell ожидайте завершения GUI-процесса через `Start-Process -Wait`.

Диагностические аргументы: `--windowed`, `--size 1280x720`, `--fps 40`, `--scale 1.5`, `--data-dir PATH`, `--demo [COUNT]`, `--page home|library|detail|settings|add|browser|keyboard|edit|empty`, `--screenshot FILE.png`, `--quit-after SECONDS`, `--benchmark`. Для демонстрации и проверки используйте отдельный `--data-dir`, чтобы не менять обычные настройки. `--scale` моделирует увеличенный масштаб в приложении, не меняя Windows DPI.

Результаты выполненных проверок и оставшиеся проверки на портативке описаны в **QA.md**. Устройство с физическим XInput и сенсорным экраном необходимо проверить отдельно. Сборка пока не подписана цифровой подписью.

Заставка для диагностики: `--no-intro` отключает её, `--intro` принудительно включает, `--intro-at 1.42` фиксирует конкретный кадр; `--screenshot-after 4` задаёт время снимка от начала процесса. Для обычных страниц `--page` заставка автоматически пропускается. `--record-intro artifacts/intro-qa/frames` сохраняет 90 кадров с виртуальной частотой 30 FPS, включая переход к библиотеке; для этого используйте `--demo 12` и отдельный `--data-dir`. Кадры можно собрать в видео через FFmpeg. Эти режимы не меняют обычную скорость заставки.

## Устройство проекта

`main` — окно, GPU и единый планировщик кадров; `ui` — экраны и фоновые события; `input` — XInput и пространственная навигация; `model` — модель игры; `storage` — SQLite; `discovery` — локальные установки; `steam_library` — лицензии и история Steam; `accounts` — подключение и библиотеки Epic/GOG; `activity` — подтверждение запуска по процессам; `platform` — Shell, Known Folders, Credential Manager, иконки; `artwork` — загрузка и ограниченный кэш текстур; `pacing` — ограничитель кадров; `wallpaper` — подключение Wallpaper Engine и жизненный цикл воспроизведения; `profile` — импорт прежнего профиля; `branding` — логотип и идентификаторы HITDROL.

Исходный логотип: `assets/hitdrol-logo.png`, предоставлен пользователем. `build.rs` подготавливает уменьшенное изображение интерфейса, значок Windows и сведения EXE. Логотип встроен в приложение; отдельная PNG-копия также включена в ZIP.

Слои заставки по приложенному пользователем изображению созданы встроенным imagegen: `assets/intro/ice-background.png`, `ice-sword.png`, `ice-wordmark.png`. Промпты сохранены в `assets/intro/PROMPTS.md`. Модуль `intro` отвечает за временную шкалу, графические эффекты и ресурсы заставки.

Оригинальный звук синтезирован без сторонних семплов: `assets/intro/ice-startup.wav`, 2,5 с, stereo PCM 16-bit / 44,1 kHz. Для его изменения есть `scripts/generate-startup-sound.py`; обычная сборка не требует Python. Модуль `startup_audio` использует Windows waveOut с одним конечным буфером, паузой и освобождением устройства. Изображения и WAV встроены в EXE.

Образцы подхода: [Playnite Fullscreen](https://api.playnite.link/docs/manual/gettingStarted/playniteFullscreenMode.html), [Winhanced](https://www.winhanced.com/). API: [egui](https://github.com/emilk/egui), [winit](https://docs.rs/winit/0.30.13/winit/), [Windows Shell](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/UI/Shell/index.html), [SteamGridDB](https://www.steamgriddb.com/api/v2). Код этих проектов не копировался. Лицензии зависимостей поставляются отдельно в `licenses`.

Публичное название выпуска задаёт файл VERSION: Beta 0.1. Числовой номер сборки Windows увеличивается отдельно, чтобы установщик обновлял предыдущие версии. Этот номер не обозначает стадию готовности продукта.
